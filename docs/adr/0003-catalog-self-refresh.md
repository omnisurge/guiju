# ADR 0003 · 目录自保鲜：进程内刷新，不依赖设备级定时任务

- 状态：**已实现**（2026-10-31）
- 决策：目录新鲜度由程序在**需要时自己维持**，不引入 cron / launchd / 常驻进程
- 影响：`search` / `which` / `pull` / `cite` 的前置行为；`sync` 的实现落点

---

## 背景

1. 目录是上游列表的**镜像**，不是索引：全量 33 页 ≈60 秒，增量 2 个请求 ≈3 秒（实测）。
2. 所有者要求：**定时任务不能挂在设备上** —— 换机器、进容器、别人来用都会失效，
   而"忘了跑"的后果是拿旧目录当现状（新公告里的书会被判成"不存在"）。
3. 旧的替代方案是让用户自己写 crontab，属于把系统责任转移给人。

## 决策

1. **抽出 `guiju/syncengine.py`**：抓取 + upsert 的唯一实现。`sync` 命令与自保鲜共用，
   两条路径不会长出不同行为。
2. **`guiju/autosync.py`**：命令执行前判断新鲜度
   - 只对**需要目录**的命令生效（`search` / `which` / `pull` / `cite`），其它命令零副作用
   - 非空且 ≤7 天 → **0 请求**直接放行
   - 为空或过期 → 抢**非阻塞 flock** 后增量抓取；抢不到锁说明别的进程在同步，跳过
   - 抓取失败 → 记 `auto_sync_failed_at`，**1 小时内不再尝试**；命令按现有目录继续执行
3. **逃生开关**：命令级 `--offline`、环境变量 `GUIJU_NO_AUTO_SYNC=1` 都不触发刷新
   （CI / 离线测试 / 只读环境用）。

## 反馈契约（不许静默）

刷新的每一种结果都必须能被 agent 读到，**不能只写 stderr**。实现方式：`cli/main.py` 把
`autosync.evaluate()` 的快照交给 `render.set_catalog()`，`render.emit()` 统一注入到每份
JSON 结果的 `catalog` 字段（命令无需各自处理，也不会漏）。

| state | 触发条件 | 给 agent 的信息 |
|---|---|---|
| `fresh` | 目录非空且 ≤7 天 | 无需动作 |
| `refreshed` | 本次刷新成功 | `new`=新增条数；结果基于**新**目录 |
| `refreshing` | 别的进程持锁 | `retry_after_seconds=30`，"建议 30 秒后重试" |
| `refresh_failed` | 刷新抛错 / 冷却期 | `retry_after_seconds`（3600 或剩余秒数），结果基于旧目录 |
| `stale` | 离线 / `GUIJU_NO_AUTO_SYNC=1` / 该命令不触发 | 明确说明"结果可能不含最新公告" |

**为什么不含糊**：agent 的典型判断是"这本书不存在"（31）。目录旧时这条结论可能是错的，
必须让它能区分"真没有"和"我只是数据旧"。

## 代价与边界

| 项 | 数值 |
|---|---|
| 常规开销 | ≤2 请求 / 7 天，发生在某一次普通命令里（≈3 秒） |
| 首次使用 | 33 页 ≈60 秒，stderr 有明确进度说明 |
| 最坏情况 | 网络不通时多一次失败尝试（≤1 次/小时），命令不失败 |
| **不做** | 不做后台常驻、不做设备级定时任务、不做并发抓取 |

## 验收

| 场景 | 证据 |
|---|---|
| 空库自动首同步 | `GUIJU_HOME=/tmp/x guiju search 防火` → 先拉 3254 条再返回结果（stderr 说明） |
| 新鲜目录零请求 | `time guiju search 防火` → 0.08s，无提示 |
| 离线不触发 | `--offline` / `GUIJU_NO_AUTO_SYNC=1` 下 crawl 不被调用（单测） |
| 失败不阻断 | crawl 抛异常 → 命令照常返回 + 1 小时冷却（单测） |
| 并发安全 | 非阻塞 flock，抢不到锁直接跳过（不排队、不重复抓） |
