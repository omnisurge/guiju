# 仓内文件裁定与实测复核 · 2026-10-30

> 裁定人：工程评审（本文件为唯一裁定书，HANDOFF 与蓝图的结论以本文件与 `ARCHITECTURE.md` 为准）
> 方法：静态阅读全部 7 个 .py、2 份文档、1 份 CSV；线上实测（35 次目录请求 + 71 次详情请求，全部走 `compliance.get`，未做任何绕过）。

## 一、三句话结论

1. **代码骨架可以留，比例约 55%**。`compliance.py` 是全仓最有价值的资产，应该成为产品的地基；`mohurd.py` 是唯一需要长期维护的部件；`db.py` 的数据模型错了一层，必须重建；`cli.py` 内容有用但**结构必须拆**。
2. **HANDOFF 的两条结论已被证伪**，其中一条（`pageSize>20` 会静默丢数据）会让团队做出错误的性能决策：实测 `pageSize=100` 全量 33 页拿到 **3254 条，与 CSV 零差异**，单页返回 99 条只是渲染上限，不丢数据。
3. **最大的缺失不是某个文件，而是版本控制**：当前目录 `fatal: not a git repository`。在一个"站点改版就要修"的项目上，没有 git 就没有回滚、没有 blame、没有 CI —— 这是 M0 第一件事。

## 三、实测命中的缺陷（可直接当 issue 提）

| # | 位置 | 现象（实测） | 影响 | 修法 |
|---|---|---|---|---|
| 1 | `compliance.get` | `check_url` 只在**发请求前**校验；`urllib` 默认跟随 30x 重定向，跳转后的 host **不再校验** | 合规白名单可被一次重定向绕过 → 这是本产品唯一的"红线级"漏洞 | 自定义 `RedirectHandler`，每个 `redirect_request` 都过 `check_url`；并禁止 30x 到非白名单 |
| 2 | `mohurd.pick_attachment` | 实测 2022-01-18「…等4项工程建设标准英文版」公告（4 个附件）**选中了《建筑设计防火规范（2018年版）》**，与公告无关 | 静默抓到**错误文件**并入库、计算 sha256、被 cite 引用 —— 比抓不到危险一个数量级 | 删除 `alive[0]` 兜底；名称匹配不到即 `verdict=ambiguous`，退出 33 报人工 |
| 3 | `mohurd.extract_codes` | 实测 4 例同页出现新+旧两个编号：`JGJ 147-2016`/`JGJ 147-2004`、`CJ/T 133-2012`/`133-2007`、`GB/T 50362-2022`/`2005`；局部修订公告原文「标准编号修改为 JGJ/T450-2018」 | `find_codes()[0]` 有一半概率命中**已被代替的旧编号** → 监理通知单引用错版本 = 事故 | codes 表加 `role`（primary / superseded_ref / target_of_revision）+ `evidence` 原文片段；判不出即 `ambiguous` |
| 4 | `cli.main` | `guiju --version --json` → `error: unrecognized arguments: --json`，**退出码 2** | 违反"agent 只读 JSON"的自家契约 | 全局 flag 挂到每个子命令 + 预解析；退出码 2 会与自家语义码混淆，需保留但文档标注 |
| 5 | `cli.cmd_search` | `return EXIT_OK if results else EXIT_OK` | 死代码，说明"空结果该不该非零"没想清 | 空结果 = 0 + `{"results":[],"hint":...}`（空集不是错误） |
| 6 | `cli.cmd_pull` | `--out` 默认 `./规范` | 会往用户当前目录写中文目录，agent 环境下不可预期 | 默认 `~/.guiju/library/`，`--out` 显式覆盖 |
| 7 | `cli.cmd_provenance` | 库中存**绝对路径**，`resolve()` 后比对；目录一改就查不到 | 溯源（M2 的核心卖点）在文件被移动后失效 | 主键改 `sha256`，路径只是缓存；溯源 = 扫文件算 hash |
| 8 | `compliance._inspect` | 只检查 `len ≤ 200KB` 且非 PDF 的响应 | 大体积 WAF 挑战页/错误页逃检 | 只对 `Content-Type: text/html` 且 <2MB 的响应做标记扫描，或抽头部 8KB |
| 9 | `compliance._throttle` | 全局单值间隔，不区分 host | 蓝图承诺"每 host 令牌桶"未实现；多源时互相拖慢 | 按 host 计令牌桶 |
| 10 | `db.Store` | 无 `user_version` / 迁移机制 | 即将改 schema，旧库会静默半坏 | 加 `PRAGMA user_version` + `migrations/NNN_*.sql` |

### 已复核并**解除**的疑点（HANDOFF 第六节）

| 疑点 | 裁定 | 证据 |
|---|---|---|
| `pageSize=100` 只返回 99 条，疑为静默丢数据 | **不丢数据，可以放开** | 33 页全量 = 3254 条、唯一 URL 3254 个；与 `标准公告全目录.csv` 比对：线上多 0 条、CSV 多 0 条。99 是单页渲染上限，不是数据缺口。全量同步从"163 页 × 1.2s ≈ 3.5 分钟"降到"33 页 ≈ 1 分钟量级" |
| 编号正则在真实详情页未验证 | **已验证，可用** | 2026 三页 3/3 命中（`JGJ 450-2018`、`GB 50333-2013`、`GB/T 50138-2010`）；54 条分层样本 33 条命中编号（61%），21 条正文确实无编号（产品标准/工作计划类），属真实缺失而非正则失效 |
| 老公告无正文 | **确认，且可量化** | 54 条分层样本：仅 28 条有附件（52%）；按年看 2014–2026 每年抽样 2/2 都有附件，2000–2013 只有零星（2001/02/04 各 1–2 例）。**产品的可得性承诺必须按年份分段写**，不能写"全库可下载" |
| 蓝图要求解析 robots.txt | 实测 `https://www.mohurd.gov.cn/robots.txt` → **404**（无 robots 限制） | 当前不解析 robots 不构成违规，但按蓝图应实现"404 视为全允许"以避免换源时踩坑 |

1. `git init` + 首次提交 + `.gitignore` + `LICENSE(MIT)` + `README.md`（含免责声明）。

5. `cli.py` 拆分 + 修 #4/#5/#6/#7。
6. `tests/`：固定样本 + `cite` 矩阵 + `compliance` 白名单/重定向单测（离线，不发请求）。
7. 全量 `sync`（33 页）→ 对账 3254 → 全量 `index`（约 3254 × 1.2s ≈ 65 分钟，可分批断点跑）。
