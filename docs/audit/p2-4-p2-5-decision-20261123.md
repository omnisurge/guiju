## P2-4：csres 默认明文回退导致默认链路不落磁盘缓存（2026-11-24 所有者决定：保持现状）

### 事实

- guiju/currency/registry.py 的默认组合根把 csres 注册为 GB/JGJ/CJJ/JTG/DB 主源，并显式 plaintext_fallback=True；注释和测试都说明站点 443 不可用。
- guiju/currency/csres.py 在 HTTPS 失败回退 HTTP 时设置 plaintext=True，并在 Completeness 里写 insecure_transport=True、complete=False。
- guiju/currency/native.py:196-207 因此不把该结果写入磁盘缓存：这是当前**有意的安全默认**，不是统计故障。
- 已存在契约测试：tests/test_currency_csres.py::CsresDefaultRegistryTest（默认注册表显式 opt-in、HTTPS 失败实际回退并标记明文、明文结果不权威）。

### 决策（2026-11-24 所有者确认）

**采用选项 1：保持现状。** 不把默认行为改成显式开关，也不缓存明文结果。

理由：

- 2026-11-24 21:00 CST 多网络实测：hk、ctyun 对 `www.csres.com:443` 均为 `Connection refused`，HTTP 80 均返回 200，站点当前没有可连接的 TLS 端点；若默认关闭明文回退，`GB/JGJ/CJJ/JTG/DB` 主源在默认配置下将不可用。
- 当前安全默认已经做到：明文结果 `complete=False`、`insecure_transport=True`、`empty_authoritative` 仅表达“源明确无记录”，且不落磁盘缓存；可用性与“不把明文结果当权威”可以同时成立。
- 显式开关/明文缓存 namespace 会扩大配置面和缓存语义，留待站点出现 HTTPS 端点或所有者另提缓存优先级时再开 ADR；不引入第二套 csres 解析器。

以下为原候选方案，保留作决策备查：

1. **保持现状（本次采纳）**：默认允许 csres 明文回退以保留主源可用性；明文结果永远 complete=False、insecure_transport=True、不落磁盘缓存。代价是重复查询会重新打上游，status.currency_endpoint/probe 可观察。
2. 若要把缓存可用性放在首位，另开 ADR，把 csres 明文回退改成显式环境开关（默认关闭）或给缓存 namespace 增加 plaintext 后缀并在命中时保留 insecure_transport 告警；必须补缓存命中/失败/告警的契约测试，且不得让明文结果变成“权威已校验”。
3. 不引入第二套 csres 解析器；不改变 403/429 现有语义。

## P2-5：M4 body_sha256/probe 底座空转（2026-11-23 round 2 已接线）

### 事实

- guiju/net/body.py 的 BodyClient 已有 probe_sink 注入点，默认 no-op；_emit/_emit_failure 会生成 ProbeRecord。
- BodyClient 由 guiju/compliance.py:_body_client() 构造，此前没有把 probe_sink 接到 Store.log_probe；pull 只在成功/坏附件路径手工调用 store.log_probe。
- body_sha256 只在 schema/文档/测试中出现，没有真实写入消费者；因此不能声称“M4 已接线”。

### 实施（2026-11-23 round 2）

1. `compliance._body_client(probe_sink)`、`compliance.download/download_bytes/get` 接受可选 `probe_sink`；`mohurd`/`shzjw` 的 `download`/`download_to` 透传。
2. `application.pull._probe_sink(store, source_id)` 把 `BodyClient` 的 `ProbeRecord` 映射到 `Store.log_probe`，观测异常不阻断下载。
3. `pull` 的 API 直连与公告附件两条下载路径均注入 sink；现有手工成功/坏附件 `log_probe` 暂保留，避免迁移期观测缺口，后续再收敛去重。
4. 未把 `body_sha256` 加进 pull 成功 JSON；退出码与 JSON 字段不变。

### 验证

- `tests/test_fix_w4_cli_20261122.py::PullOneCachedShapeTest.test_cached_10_keeps_success_metadata_and_finalize_path` 现同时断言 `Store.log_probe` 收到 `ProbeRecord(url,status=200,bytes,outcome=ok)`。
- `tests/test_net_idn_probe.py::...::test_truncated_probe_sink` 仍验证 BodyClient 截断路径的记录。
- 全量 1223 tests 与 3.10/3.13、CI 另行记录在 B5 门禁。

### 过渡

尚未删除 pull 的现有手工 `log_probe` 调用；probe sink 已接管 BodyClient 的请求级记录，手工调用保留为过渡兼容，后续版本再做去重。
